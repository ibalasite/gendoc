§1. Executive Summary

This document describes the engineering design of the pixel-pet-arena project, including architecture, data model, API design, and operational concerns. It covers 21 sections in total.

§2. System Architecture Overview

The system follows a Modular Monolith pattern with 6 Bounded Contexts: Identity, Pet, Arena, Leaderboard, Marketplace, and Admin.

§2.1 Context Map

Inter-BC communication uses Domain Events for async + Public APIs for sync.

§3. Technology Stack & ADRs

Backend: Node.js 20 / Fastify 4. Database: PostgreSQL 15 (Supabase). Cache: Redis 7 (Upstash). Frontend: React 18 + Phaser.js 3.

§3.2 ADR-001: Backend stack

Chose Node.js + Fastify over Go/FastAPI for team velocity.

§4. Module / Component Design

Each BC is a separate module under apps/api/src/<bc>/ with its own routes, services, repositories.

§5. API Design

RESTful endpoints under /api/v1/* for player, /admin/api/* for admin.

§6. Data Model

12 PostgreSQL tables + 6 Redis key patterns. Cross-BC FKs forbidden.
